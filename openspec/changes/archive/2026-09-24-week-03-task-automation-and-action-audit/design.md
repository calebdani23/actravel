# Design: Week 03 Task Automation and Action Audit

**Result: READY FOR TASKS.** Amended scope supports four product workstreams decomposed into **13 behavior-complete native slices**. Forecasts include proof/types/task/living-doc updates and ≥25 lines of headroom below 400. Total >1,200 automatically splits into packets.

## Approach and Decisions

Use additive database ledgers/projectors in order `0077` audit → `0078` actions → `0079` foundation → `0080` sources. Confirmed policy is Mexico City business time; later creation/first-valid-assignment anchor; one transferable Task per Opportunity; explicit audited contact completion; exact response/payment/version-state cancellation; unambiguous WhatsApp only; unresolved invalid ownership; closed action metadata; current-authority replay; first-terminal-wins; future-only automation.

## Exact Contracts and Data Flow

Let `C` be `follow_up_canonical_json`; `H(x)=lowerhex(SHA256(UTF8(C(x))))`.

**`0077`.** Receipt result is exactly `{schema,receiptId,requestId,taskId,actorKind,actorId,ownerId,action,fromStatus,targetStatus,cancelReason,completionOutcome,note,sourceKind,sourceId,sourceKey,sourceOrder,outcome,createdAt}`, schema `task-action-result.v1`, canonical lowercase UUID/RFC3339-microsecond strings, canonical byte count, and hash `H([schema,receiptId,requestId,taskId,actorKind,actorId,ownerId,action,fromStatus,targetStatus,cancelReason,completionOutcome,note,sourceKind,sourceId,sourceKey,sourceOrder,outcome,createdAt])`; `replayed` is return-only. INSERT rebuilds shape/hash and human-null versus automation-cancel source rules; UPDATE/DELETE fail. Forced RLS uses the current role matrix against immutable owner snapshot.

**`0078`.** Human fingerprint=`H(["task-action-request.v1",requestId,actorId,taskId,targetStatus,cancelReason,completionOutcome,note])`; request key=`H(["task-action-request-key.v1",requestId])`; automation key=`H(["task-action-automation-key.v1",sourceKind,sourceId,sourceKey,sourceOrder,taskId])`; automation fingerprint=`H(["task-action-automation.v1",sourceKind,sourceId,sourceKey,sourceOrder,taskId,"canceled","source_invalidated"])`. After authentication/input validation: receipt lookup/classification under request lock → authoritative Task lock/current authorization (`receipt.taskId` when found) → replay/conflict return → lifecycle/append. Grant replacement precedes legacy `task_transition` revocation. `lib/admin/task-actions.ts` accepts only `{requestId,taskId,targetStatus,cancelReason,completionOutcome,note}`; only malformed/provider results add `PERSISTENCE_FAILURE`; `lib/admin/tasks.ts` loses `transitionTask`.

**`0079`.** Preserve `0064` manual/exact-`follow_up` predicates. Native rows require `automation_origin_key=idempotency_key`, null legacy provenance, microsecond due, and exact lead-only `Complete first contact` or quote-only `Follow up on quote version` shape. Deferred parity is immutable. Origins admit only `(first_contact,opportunity_assignment,generate)` or `(quote_follow_up,quote_sent,generate)` and keys `H(["task-automation:v1",kind,opportunityId])` or `H(["task-automation:v1",kind,quoteVersionId,sentEventId])`. Outcome matrix is exactly `opportunity_assignment→generate|transfer;opportunity_unassigned|opportunity_archived|opportunity_terminal→cancel|suppress;quote_sent→generate;quote_version_response|quote_accepted|quote_rejected|quote_expired|quote_cancelled|quote_superseded|whatsapp_inbound|payment_verified→cancel|suppress`, keyed by `H(["task-automation-outcome.v1",sourceKind,sourceId,sourceKey,operation,originKey])`. Calendar payload is exactly `{"schema":"mx-calendar.v1","zone":"America/Mexico_City","tzdb":"2024a","valid":["2026-01-01","2031-12-31"],"offsetSeconds":-21600,"weekdays":[1,2,3,4,5],"hours":["09:00","18:00"],"holidays":["01-01","firstMonFeb","thirdMonMar","05-01","firstSunJun:y%6=2","09-16","10-01:y%6=2","thirdMonNov","12-25"]}` with rule hash `H(["task-due-calendar.v1",payload])`; host tzdata is forbidden, unsupported dates fail, and changes create v2.

**`0080`.** Persist cutoff and immutable suppression tombstones for pre-cutoff/invalidation-before-generation facts. Lock source identity → origin/tombstone → Task → receipt; preserve `contacts→leads→quotes→quote_versions→documents→quote_upload_intents`; allocate immutable `source_order`. Transfer changes only active owner. Task/origin/outcome RLS follows current Task owner; ownerless outcomes/tombstones are Admin-only; receipts use snapshot RLS. Add authenticated `crm_record_quote_version_response(requestId,expectedActorId,quoteId,quoteVersionId,channel)`, channels `phone|email|whatsapp|portal|other`, and payload `{schema:"quote-version-response.v1",requestId,quoteId,quoteVersionId,channel,actorId}`; no UI caller.
