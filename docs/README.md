# AC Travel documentation map

Use this file as a directory map, not as a substitute for the active implementation context.

## Active implementation

- `implementation/ACTIVE.md` — current week, active change, gates and next action.
- `implementation/README.md` — progressive-context rules, authority order and 12-week program.
- `implementation/weeks/` — concise milestone briefs; only read the active/referenced week by default.

## Approved Blueprint context

- `blueprints/INDEX.md` — topic router.
- `blueprints/VOLUME_I_BUSINESS.md` — business operating model and rules.
- `blueprints/VOLUME_II_PRODUCT.md` — product surfaces, workflows and UX architecture.
- `blueprints/VOLUME_III_TECHNICAL.md` — target technical architecture and implementation roadmap.

## Living repository references

- `DECISIONS.md` — durable technical/product decisions.
- `PROGRESS.md` — verified implementation history and known gaps.
- `ENVIRONMENT.md` — environment/runtime configuration reference.
- `OPERATIONS.md` — production operations/runbook; verify environment-specific values before executing commands.
- `about/` — public brand/about content references, not implementation authority.

## Historical archive

- `archive/README.md` — archive rules and inventory.
- `archive/mvp/` — superseded MVP-era master prompt, roadmaps and sprint plan.

Files under `archive/` are never active instructions. They are provenance only.

## Authority reminder

For implementation conflicts, use the order defined in `implementation/README.md`: active change → executable code/schema/tests → active week brief → Blueprint III → Blueprint II → Blueprint I → archive/provenance.
